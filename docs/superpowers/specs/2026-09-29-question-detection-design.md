# 课堂问题判定与问题片段提取设计

**日期：** 2026-09-29  
**状态：** 已确认，进入实现

## 背景

当前检测器主要依赖疑问词、句末语气词和问号。它能较快发现“哲学的基本问题是什么”，但无法稳定区分讲解、课堂管理和真正需要回答的问题。

对录音《9月16日 马克思主义哲学与辩证法课程讨论.m4a》的后 40 分钟回放显示：577 个最终转写产生了 113 个候选。候选中同时出现了以下几类内容：

- 应回答的教材问题：“哲学的基本问题是什么”“物质和意识的辩证关系是什么”；
- 应回答的题目问题：“第五题选哪个”“划分唯物主义和唯心主义的唯一标准是哪个”；
- 讲解中的嵌入短语：“其次呢我们又了解了什么是世界观”；
- 未完成的 partial：“马克思主义是如何……”；
- 课堂管理或确认：“李信同学在吗”“声音大一点”“答案不就在这里吗”。

## 目标与边界

目标是只把有明确作答任务的内容发送给大模型，同时保留完整转写供用户查看：

1. `academic_qa`：教材概念、定义、关系、原因、分类、回忆题等知识问答；
2. `choice_qa`：第几题选哪个、哪一项正确、属于哪一类等题目问答。

以下内容不创建回答卡片、不调用模型，但仍保留在转写流中：

- `management`：点名、在吗、声音大小、听题目、课堂操作；
- `confirmation`：孤立的“对不对”“是吧”“答案不就在这里吗”等确认或反问；
- `lecture`：没有完整问句的讲解、过渡和教材朗读。

重复的教材问题不跨段强制合并，保持当前“实时展示重复问题”的行为。

## 方案选择

采用本地混合判定，不增加额外的分类模型或 API 请求：

- 规则和有限状态用于保证低延迟、可解释和离线可测试；
- 课程热词用于识别教材主题和提高问题片段的可信度；
- 句法/话语边界用于从长段讲解中提取最后一个完整问题片段。

不采用“继续堆叠关键词”作为唯一方案，因为疑问词出现在讲解内部时会误报；不采用每句话调用 LLM 分类，因为它会增加课堂延迟和成本。

## 判定流程

### 1. 文本预处理

保留当前课程纠错和归一化流程，然后去掉明确的称呼前缀。对“李卓阳哲学的基本问题是什么”“陈林西第三题选哪个”这类 ASR 结果，只在后半句出现课程主题或题目结构时删除疑似姓名，不对任意两到四个汉字盲删。

### 2. 问题片段提取

按句末标点、话语连接词和课堂结构词切分长文本，优先保留最后一个完整的疑问片段。例如：

```text
哲学是系统化理论化的世界观……所以诸位哲学的基本问题是什么呀
                 -> 哲学的基本问题是什么
```

只有当片段自身具有完整疑问结构时才保留。嵌入在“我们又了解了什么是世界观”中的“什么是”不在句末，因此归为讲解。

### 3. 类型判定

判定按以下优先级执行：

1. 明确的课堂管理模式优先过滤；
2. 明确的学术/题目问句优先保留；
3. 孤立确认或反问过滤；
4. 长度、课程热词、问句完整度和话语过渡词作为补充分数；
5. 无法稳定判断时不调用模型。

“对不对”只有在同一片段中同时存在明确教材命题或题目内容时，才作为知识问答处理；单独的“对不对”不处理。

### 4. partial 稳定性

partial 仍允许提前触发，以保持即时回答，但必须同时满足：

- 问题片段位于文本末尾；
- 具有明确的教材/题目语义；
- 不是“是如何”“是怎么”等明显未完成尾部；
- 没有被管理、确认或讲解模式否决。

不满足条件的 partial 只进入转写，不创建回答卡片；final 事件可以在完整问句成立时创建候选。

## 接口和实现边界

`QuestionDetector.feed()` 继续返回现有 `QuestionCandidate`，避免改变 UI、pipeline 和 DeepSeek 接口。类型判定和问题片段提取封装在 `question_detector.py` 内部，最终只向 pipeline 暴露可回答的问题文本。

测试覆盖：

- 录音中出现的教材问句和选择题；
- 讲解嵌入疑问词、未完成 partial；
- 点名、课堂管理、确认反问；
- 长句问题片段提取；
- 原有问题 ID、partial/final 修订和重复行为。

验收时使用同一段 40 分钟录音回放，记录候选数量、代表性误报/漏报和从 ASR final 到候选产生的延迟。离线回放结果不冒充真实麦克风延迟。
