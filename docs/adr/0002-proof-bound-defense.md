# 答辩答案按逐条证据组装

日期：2026-10-16。

## 背景

真实系统回放的多轮来源审读发现，即使引用编号有效，普通自由文本回答仍可能把一种
模型的实验结果转给另一种、把特定配置外推为整个模型类，或在口述总结中把用途分工
加强为排他结论。仅补提示词没有消除这些实际错误。

## 决定

生产答辩管线直接请求结构化资料结论，不先生成自由文本草稿。请求只带原始当前问题
与本次本地检索的同一批候选片段，最多五项；候选保留正文与有界章节上下文。会议
背景仍只参与本地检索，没有追加资料检索，也不外发草稿、历史回答或其他派生载荷。

返回值只允许 `status` 和 `claims`。本机给 `excerpt` 与 `section_context` 的原文单元
编号，每单元不超过 500 字，各单元拼接须与原片段逐字符相等，没有新增或重复正文。
模型只选择候选、字段与单元编号，本机回填该单元的精确原文，避免模型复制引文时
改写标点或条件。每项结论必须绑定这些来源。完整接收后，本机拒绝重复 JSON 键、额外字段、
未知编号、空或伪造引文、超量响应，以及绕过证据绑定的首段或总结，再逐条组装
【资料事实】和来源标注。`partial` 或 `insufficient` 的不足提示与补证建议由本地
固定文案提供，不用未受约束的生成总结补齐。

原有课堂流式行为保留。答辩不把生成中的 JSON 或任何未通过校验的文本交给卡片；
截断、协议错误、传输失败均显示错误，答案保持空白，不回退自由文本，也不自动重试
这一次结构化请求。取消、问题修订和关闭继续由同一回答任务持有并关闭请求流。

## 证据边界

精确引文校验能证明引文来自本次候选，不能以程序方式证明结论被原文语义蕴含。
生成规则仍须逐项检查主体、比较双方、数值角色、条件、版本与文稿/规范/完成状态；
真实答案还必须接受逐句来源审读。受控系统播放测试也不等于实际会议噪声及全部
专业词准确率评估。

曾拟发送既有失败草稿作独立云端复核；自动审批以超出“只发送问题和命中片段”的
授权范围拒绝，脚本未执行、请求为零。该方案已撤除，本决定采用的请求不含草稿。
对应拒绝收据为 `tmp/grounding-probe-rejected.json`。

`run-10` 的首请求以 `stop` 返回，但旧的模型复制引文协议未通过精确匹配；卡片正文
保持空白，后三题未播放。该失败记录保留。原文单元编号是对此协议可靠性的后续修复，
不能把拦截本身写成问题已成功回答。
