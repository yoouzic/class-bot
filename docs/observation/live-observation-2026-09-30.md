- 麦克风就绪：入口启动后 11.859 秒；停止完成：131.937 秒。
- 187 条转写事件，其中 11 条最终转写。

- 其中一张卡片发生 22 次不同问题文本修订、22 次回答启动，停止时尚未完成。另有两张卡片的候选在最终转写时没有重新通过检测，但此前已启动回答。
- 日志中的 ASR confidence 恒为 0.0，不能拿这个字段直接设定识别质量阈值。检测器的 0.5 分数阈值是启发式分数，并不是经过标定的正确概率。
- 已完成卡片的首次完整回答距首次候选约 2.797—9.140 秒；这不是老师问完后的延迟，也不代表整节课性能。

## 可以核验的问题

1. 抢答和反复启动：候选“呃很个贵的的问啊在什么样的情”尚未完整就进入回答；后续修订继续启动。当前 pipeline 在新候选、问题文本变化或背景变化时立即启动或重启回答。
2. 教材命中不代表相关：最终候选“呃一个珍的的问题在什什么样的情况下呢”得到关于革命成功后措施、未来社会的回答，并附 PDF 第 335 页。现场随后转写围绕实验、认识与实践；这段回答与可见上下文不相符。课程配置正确仍会出现相关性问题。
3. 真问题漏检：现场长段末尾“我们的认识的过程有哪些呢”没有生成对应新问题卡片。独立文本重放相同句子仍检测不到；“我们的认识过程有哪些”和“实践认识再实践再认识是怎样的过程”也漏检，而“认识的过程是什么”可以触发。不能据此计算召回率，尚无完整人工标注。
4. 口头确认误触发：“做实验呀多靠是不是”“在这个当中表现的不利利人是不是”等残缺句触发卡片。含“是不是”不等于一个完整、可回答的问题。
5. 连续讲话形成长段：一次最终转写段长约 30.9 秒，含大量前文和末尾新问题。只依赖静音结束会延迟完整转写；只提高静音阈值不能解决这种连续讲话。

## 建议的规则顺序

以下是待对比验证的起始方案，不是已测得的最优配置。

| 环节 | 建议规则 | 本次依据 |
|---|---|---|
| 问题识别 | 覆盖“有哪些、怎样、哪几种、分几次”等问法；以独立子句识别，避免整段一票否决 | “认识的过程有哪些呢”可复现漏检 |
| 完整性 | 必须具备讨论对象和问题意图；“在什么样的情”“能不能…”先等待 | 残缺句已触发回答 |
| 提交时机 | 实时候选可先展示；候选完整且关键文本稳定 600—900 毫秒后再请求，或等待最终转写；先试 700 毫秒 | 同一张卡片 22 次启动 |
| 修订与失效 | 同一问题合并更新；口头填充或标点改变不重启；最终转写否定候选时撤销等待任务并标记失效；只有主题或条件实质改变才重新回答 | 非最终候选在最终转写未通过仍保留回答 |
| 口头确认 | “是吧、对吧、是不是”单独出现或附在讲解结尾时，默认只转写；完整命题且明确要求判断时允许回答 | 现场确认式残句误触发 |
| 上下文 | 保留近期约 20—40 秒、限长的相关主题背景；简短追问绑定最近问题，题目显示原话，补全另作说明 | 残缺题目被猜成其他教材问题 |
| 教材检索 | 用题目中的学术对象加背景检索；只匹配通用词不视为有效证据；相关性不足时不附猜测页码 | 通用“情况下”触发无关教材答案 |
| 连续语流 | 在 ASR 实时文本上做子句级判断；最长 8—12 秒可滚动检查，不把强制音频切段直接等同于问题结束 | 30.9 秒长段含新问题 |
| 断句参数 | 保留当前 320 毫秒作为基线，比较 450 和 600 毫秒；同时测短句拆断和最后问题延迟 | 当前样本不足以直接确定静音最优值 |
| 输出 | 默认先给 1—2 句核心答案；题意不足显示“等待补全”，不得自行猜题；复杂题再展开 | 已看到无关回答与空答 |

## 怎样选参数

先从当前日志人工标注真问题、确认句、讲解、噪声及对应上下文；还需核对听到的原话，ASR 文本不能作为唯一真值。然后在后续 10—15 分钟课堂观察里比较两个模式：

- 保守模式：仅完整最终转写提交，作为误触发较少的参照；连续讲话时可能较慢。
- 平衡模式：完整候选稳定约 700 毫秒提交，最终转写复核并修订；推荐作为第一组试验。

比较误触发数、真实问题漏检数、每题任务启动数、问完至首个有用答案的延迟、教材相关性。目标是每个问题通常只启动一次回答，并降低无关回答；单纯追求更多卡片或更快触发不能证明规则更好。此次不报告准确率、不声称参数最优。

## 后续修复与验证

用户授权修复后，已落实以下变更：

- 检测器支持“哪些、怎样、哪几、哪两、分几”，添加认识、实践、真理等主题提示；长讲解尾部的短枚举问题可以单独提取。
- 明显残缺的“在什么样的情/情况下”等句子不提交。连续讲话中的“是不是”确认尾句先等待最终转写复核；完整“实践是不是检验真理的唯一标准”仍能在最终转写触发。
- 非最终候选默认等待 700 毫秒稳定；完整最终候选可立即提交。快速修订替换等待任务，同一题末尾“呢/啊/呀/吧”变化不重新请求。
- 独立问题的背景转写变化不重启回答；依赖“这个/那个/它/还有”等指代的问题仍能用更新背景修订。
- 最终转写不再支持候选时，取消任务、清除未确认答案。停止监听会取消稳定等待任务。空的取消卡片显示“已取消回答”。
- 上下文超过 320 字时保留最近的讲解，不再由较早长段挤掉最近说明。
- 教材检索剔除通用问句词和口头框架，避免“什么样的情况下”单独命中无关页；模型提示明确禁止残缺题目猜题作答。

验证：`python -m pytest -q` 共 **229 passed**；`python -m ruff check src tests` 通过；`git diff --check` 无空白错误。

按原始转写事件的时序进行 10 倍速离线回放，700 毫秒等待同比缩放为 70 毫秒，使用立即完成的本地占位回答，没有重新录音、跑 ASR 或调用 DeepSeek。原始现场记录的回答任务启动数为 40；修复后该回放启动 2 次，占位客户端也被调用 2 次，对应“认识的过程有哪些”和讲解末尾的“哪两次……”问题。另一个观察结束时仍在修订的候选被取消。回放无管线诊断错误。
