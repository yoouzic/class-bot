## 验证入口

`scripts/defense/verify_live_defense.py` 使用已选场景的真实完整索引，以及生产入口
`WorkspaceController.prepare_session()` 和 `RuntimeController.start()`。
它保留原始构造器，并在实际对象的方法旁记录观测事件：

1. 本机 Windows Huihui 中文 TTS 生成受控 WAV。
2. `winsound.PlaySound` 在 Windows 默认播放端点真实播放。
3. 默认 `LoopbackCapture` 从 WASAPI 回环读取，记录帧计数和峰值，不保存采集音频。
4. 原有 `SpeechSegmenter`、`FunAsrStreamingRecognizer`、`DefenseQuestionDetector` 处理。
5. 原有答辩 `LivePipeline` 经 `DeepSeekClient.prepare_answer_with_local_context()` 查询真实本地向量与关键词索引，背景仅用于本地查询。
6. 当前答辩路径使用 `DeepSeekClient.grounded_answer()` 单次结构化生成；只发送当前问题与同次检索片段，严格校验每项事实的精确引文后，本地组装文本并一次更新卡片。旧轮次的自由流答案仅保留作历史证据。
7. `--show-window` 使用真实 `MainWindow` 和 qasync；核对窗口持有的卡片状态、答案和来源，保存该窗口截图。

没有转写文本注入或直接给识别器喂 WAV/PCM 的快捷路径。未指定 `--run-live`
时不会采集或请求 API。索引缓存过期/缺失时拒绝重建；语义编码保留实际本地
BGE 编码器，验证阶段仅允许查询编码，不允许整库重新编码或下载模型。

先等完整索引已发布、同一播放端点没有其他验证采集任务，再运行：

```powershell
.\.venv\Scripts\python.exe scripts/defense/verify_live_defense.py `
  --questions-json tmp/live-defense-20261016/questions.json `
  --output tmp/live-defense-20261016/run-01 `
  --wav-dir tmp/live-defense-20261016/tts `
  --scenario-id 4f37a40efc3c4ea2bb491c73f3ac0a44 --cpu-threads 4 --run-live --show-window
```

重新生成受控中文输入：

```powershell
.\.venv\Scripts\python.exe scripts/defense/verify_live_defense.py `
  --questions-json tmp/live-defense-20261016/questions.json `
  --output tmp/live-defense-20261016/tts `
  --wav-dir tmp/live-defense-20261016/tts --prepare-tts
```

`questions.json` 是对象列表，每项含安全文件名 `id`、朗读文本 `text`、
ASR 与自动问题必须包含的 `expected_terms`，以及可选的来源文件名正则
`expected_sources`。多个来源正则须分别命中；一个正则可用 `|` 表示候选来源。
`expected_question_groups` 分别指定每个子问必须出现在实际自动问题文本中的主题词。
`expected_answer_status="insufficient_basis"` 允许明确无依据且无伪造来源的回答不含 `[Sn]`。
`recognition_review_terms` 单独记录需要核对的专业词是否原样保留，不能以主题通过替代识别准确率。

## 收据与判定边界

每次运行输出本地 `events.jsonl`、`summary.json`，以及可选的窗口 PNG。
收据记录播放起止、WAV 摘要、回环非零帧、VAD 起止、实际 ASR 终稿、自动问题、
检索耗时、实际检索命中全文/路径/位置/分数、实际发送的匹配片段、流完成、卡片终态、
来源、首字/完成时间及资源释放。全部实际命中和卡片保留在本地供逐条支持性核查。
不会输出 API 密钥；只向配置中的 `https://api.deepseek.com` 发送问题及检索候选。

自动通过要求所有链路阶段齐备，ASR 终稿和自动终稿包含预期主题；最终卡片仍为
`answered`，检索与完成流属于该问题，回答使用的 `[Sn]` 均在实际来源列表内。
后来被取消的卡片、不同问题的成功流、无播放的注入、未知来源编号均不能覆盖失败。
有停顿的整题可使用实际终稿的合并文本和实际候选携带的上下文核对主题；每个要求的子问
仍须出现在实际候选文本中，并且每个终稿候选的最后卡片都须完成。切换下一题前等待
实际回答任务结束，避免后续收据混入上一题的回答。

**自动通过仍需人工核对片段是否逐条支持回答。** 来源编号存在并不证明内容正确；
受控 TTS 也不代表真实会议口音、噪声、多人重叠或后续追问的识别质量。

当前新轮次还必须具有 `grounded_answer_start/request/complete` 完整链，实际 HTTP
的 user JSON 只能含当前原问题和同次候选 `evidence`。每个回答仅一次请求，默认
thinking disabled、max_tokens 2500；不调用自由 `stream_answer`，不生成或外发草稿。
返回仅含状态与绑定引文的事实列表，本地拒绝未知编号、错误字段和非精确引文，
只组装事实及固定的资料不足/补证句。完成本地校验前卡片正文及增量回调均为空，
完成后只能一次发布与该结果完全一致的文本；引文仍须人工核对是否支持整项事实。

run-10 之后的原文单位协议将每个正文/章节字符串无损切成最多 500 字符的有序单位，
正文编号 `E1...`、章节编号 `C1...`，发给模型的每项字段为 `{unit,text}` 列表。原问题、
来源元数据、候选顺序均不变，各单位 `text` 拼接须逐字等于原完整字段。模型引用只
选择 `{id,field,unit}`，精确 quote 由本机按该单位全文回填；不让模型重新抄写引文，
也没有模糊匹配或缩减原片段。脚本独立验证无损拼接及对应关系，不调用生产切片算法

不记录 reasoning 或密钥，也不把该响应再发给外部服务。

核验脚本单独记录同卡片、同问题版本、同 prepared 对象、真实出站字段及引文。
其他问题的完成事件、缺少请求链的伪完成、较早坏版本均不能为提前正文背书。

### 四线程设置的范围

只读检查应用 `main()`、PowerShell/批处理启动器和配置代码，没有统一设置 Torch、
OMP、MKL 或 inter-op 线程。当前安装的 FunASR `AutoModel` 自己会读取 `ncpu`，
未配置时取 4，并在建模及推理准备阶段调用 `torch.set_num_threads(ncpu)`；
当前缓存流式模型配置未覆盖 `ncpu`。因此 `--cpu-threads 4` 与该版本 ASR 加载后的
默认线程数一致，但额外把识别器启动前的索引缓存/语义模型预热也限定为四线程。

这类收据只证明四线程测试进程中的时间，不能推定应用未设置线程时的启动/索引预热时间，
也不代表 inter-op、其他本机音频库或其他机器的性能。完整收据分别记录请求线程数、
ASR 前后实际 Torch 线程数、inter-op 数和识别器实际 `ncpu`。上述默认值来自安装代码的
只读检查；这一轮默认设置审查没有加载模型。
