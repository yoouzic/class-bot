# 实时标点与问题识别优化

2026-11-02，围绕"保实时性提转写质量"与"更准地识别是否在问问题"完成一轮调研与实施。调研参照：FunASR 官方 2pass 实时管线（流式 ASR + 实时标点）、Dolphin（DataoceanAI/清华，WeNet 两 pass 中文流式模型）、FireRedASR（小红书，1.1B AED 中文 CER 3.18%）、CT-Transformer 标点模型族。

## 一、实时标点器（已实施）

**问题**：流式模型输出无标点，问题检测器在实时路径上失去最强信号（`？`，打分 +0.65）与子句边界，只能靠关键词标记。

**方案**（FunASR 官方实时管线同款模式）：新增 `src/classbot/asr/partial_punctuator.py`，用小模型 `ct-punc-c`（约 290MB）对每条 partial 重新加标点后发射。实测 GPU 延迟：20 字 8.7ms、94 字 57.5ms，远低于 partial 每 1–3 秒一次的节奏；集成在识别器 `_infer` 发射路径，失败或未加载时降级为原始文本，内部累积文本保持不变。配置 `CLASSBOT_ASR_PARTIAL_PUNC`（默认开），模型按设备热缓存，随会话后台预加载。

**附带收益**：界面 partial 可读性提升；检测器的子句切分（`[。！？；]`）在实时路径生效——正是 live-observation 文档建议的"在 ASR 实时文本上做子句级判断"。

## 二、问题检测器评测基座（已建立）

从 9 月 16 日录音的离线精修转写抽取 150 条子句（覆盖全录音、去重），由 AI 逐条标注（q=完整可回答的问题，含老师自问自答的设问与向学生提问；n=陈述、确认尾句、残缺、噪声；41 q / 109 n）。标注文件随仓库留存供复核：`tmp/eval-asr-20261101/clause-sample.json` + `clause-labels.json`，评测脚本 `scripts/eval/eval_question_detector.py`。**标注是 AI 完成的可复核基线，不是人工真值。**

| 指标 | 基线 | 优化后 |
|---|---|---|
| 查准率 | 0.800 | **0.907** |
| 查全率 | 0.488 | **0.951** |
| F1 | 0.606 | **0.929** |

## 三、检测器修复清单（全部由评测数据驱动）

误杀修复（查全 0.488 → 0.951 的来源）：

1. 不完整尾巴（"是哪个/是如何"）原来不分 partial/final 一律拒绝，"唯一标准是哪个呀"这类完整问句被误杀；现在仅 partial 拒绝，final 放行。
2. 长问句无学术提示词即丢弃；新增"问句形态证据"豁免（句末疑问结尾、疑问词开头、究竟…还是等），并补充提示词：联系/矛盾/规律/本质/现象/实体/理念/定义。
3. 标记表补缺："会不会""在哪""哪里""怎样/怎么样""哪一个""哪几个""究竟"；"是什么"倒装句式；"对的…还是"判断选择问。
4. 最小长度 8→7："意识是谁的机能"这类短完整问句放行。

误报修复（5 → 4，剩余 4 条均为转写破损文本）：

1. "就是**是否**认联系"——"否认"被切成"是否"子串；是/否相邻后接"认/定"时不再视为疑问。
2. "不**能不能**等"——"能不能"跨字生成；前缀为"不"时跳过。
3. "不管…发生**什么**"——不定代词；span 补救路径遇到不管/无论/任何/随便时跳过。
4. "这个大家能理解吧"——理解性确认尾句新增拒绝清单。

顺带修复：教师答案裁剪器原来只要后文任意位置出现"答案/正确"就截断问题（"带着你自己的一个答案"被误截），现在要求提示词位于后缀开头；学生姓名剥离不再吞掉"属于主观"等动词短语。

遗留（词法不可达，需语义模型）：无疑问词题干（"…它的方法论要求是"）与重复破损转写（"第一个层面是什么什么"）。

## 四、未实施但已调研的选项

- **Dolphin 流式模型**（WeNet 两 pass 一体）：架构优雅但需引入 WeNet 运行栈，迁移成本高，当前 2pass 已覆盖其价值，暂缓。
- **FireRedASR-AED（1.1B）替换离线精修**：中文 CER 3.18% 优于现有 SeACo，但无热词机制且推理更重；如追求极致质量可实测对比。
- **SenseVoice-Small 替换精修**：更快（官方称 10s 音频约 70ms）但无热词；本录音评测显示热词密度 +16%，SeACo 更契合术语密集场景。
- **检测器语义升级**：可用项目内已有的 bge-small-zh 向量做问句/陈述句相似度作为第二信号，或积累标注后微调小分类器；待标注集扩大后评估。

## 六、追加（同日）：日常泛化、卡壳折叠与网络检索兜底

### 检测器泛化（评测集扩到 170 条：新增 20 条日常对话与卡壳样本）

| 指标 | 课堂 150 条时 | 泛化+卡壳修复后（170 条） |
|---|---|---|
| 查准率 | 0.907 | **0.926** |
| 查全率 | 0.951 | **0.980** |
| F1 | 0.929 | **0.952** |

新增能力：

1. **卡壳/口误折叠**：三连及以上单字（是是是→是）与二连及以上双字（这个这个→这个）在问题抽取前折叠；单字二连保留（想想/常常/刚刚是有意义叠词）。"到底是是怎样传递的"这类答辩常见卡壳可正常识别。
2. **日常对话式询问**：纯"…吗"问句（"支持中文吗"）长度 ≥10 时放行（短句仍被最小长度拦截，管理用语仍被拒绝）；"多少度"类单位后缀、"哪一层"、"什么时候"、"…来着"问尾、"到底+疑问词"全部纳入。
3. **"X着呢"状态语气**（"文件放着呢"）与疑问"呢"区分，不再误报。
4. bge-small-zh 零样本语义分类实验：**诚实负结果**——单独最佳 F1 仅 0.518（92 条陈述误判为问句），任何与词法融合的方式都把 0.952 拉低到 0.36–0.79。检索式嵌入不适用于破损 ASR 文本上的疑问/陈述判别，词法+标点信号是当前最优路线；结论存档避免重复尝试（实验脚本为一次性，模型在 `tmp/experiment-bge/`）。

### 网络检索兜底（`CLASSBOT_WEB_SEARCH`，默认开）

- `src/classbot/llm/web_search.py`：**首选 DeepSeek Search API**（`POST /v1/tools/search`，复用已配置的 base_url 与 API key，query 上限 128 字符，结构化返回 title/url/snippet；约 $0.75/千次成功请求）；无 key 或 API 失败时降级到无密钥渠道（Bing 跟随 cn.bing.com 重定向按 `b_algo` 块解析，DuckDuckGo 兜底）。任何失败返回空并静默降级。真实 DeepSeek API 活体验证：4 条权威结果（社科院马克思主义研究网、知网词条）525ms。
- **课堂模式**：教材候选缺失时不再只回"教材页码未匹配到"，改用网络检索候选作答，句子标注（网络：标题），卡片来源列为"网络检索：标题 URL"，系统提示明确"未经本地核实、不得冒充教材"。
- **答辩模式**：本地证据核验链保持权威不变（网络候选绝不进入本地编号体系）；`grounded_answer_with_web_fallback` 仅在核验结论为 insufficient 时触发，输出独立段落并以【网络检索参考】开头，明确"本地资料未命中、未经核验、可能过时"。管线优先调用该钩子，旧客户端自动回退原接口。
- 关闭开关后行为与旧版完全一致（测试覆盖）。本地纪律类测试（核验、请求契约）以 autouse fixture 固定离线运行，网络兜底行为由专门测试覆盖。
