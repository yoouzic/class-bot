## 真实分词器暴露的全文覆盖错误

首次 CPU/GPU 数值对照虽然一致，但两条只在尾部结论不同的长文本产生完全相同的向量。
检查真实已缓存的快速分词器后发现：请求 `truncation=True` 和 overflow，长输入仅保留
512+68 个 token，尾部结论没有进入任何窗口。仅用模拟 overflow 的旧测试不能发现这个问题。

V2 先取得不截断的完整 token 序列，再显式切分每窗 510 个正文 token、64 个重叠 token，
通过原分词器添加特殊 token 和 mask，最后分批计算与单位归一化池化。
真实本地分词器回归逐项核对 token ID、特殊 token、mask、混合长度及尾部覆盖；
缺少快速后端时使用完整的 slow tokenizer 接口，接口不足则明确失败。

编码身份升级为 `cls-window512-stride64-unit-pool-v2`，并加入索引身份、恢复进度和
精确文本缓存身份。先前 1,472 行 V1 CPU 进度不能复用，保留的旧文件不作为可检索快照。

## 实际中断与恢复保护

16 项直接回归覆盖短暂占用成功、持续失败保留旧字节、临时文件清理及恢复覆盖未提交后缀。

## 重复来源路径校验与原环境重载

280,788 个片段对应 4,934 个源文件。原加载器对同一文件的每个片段重复做绝对路径解析；
现只在首次遇到各来源时检查路径格式、已知文件成员及解析后仍在资料根目录内，后续复用
该已验证路径。每个片段的文本、定位、类型和长度仍逐项校验，源内容 hash、元数据与
向量摘要、维数、有限值及单位范数检查均保留，没有改变缓存身份或检索排序。

独立原 CPU 环境 CacheOnly 重载拒绝任何缓存缺失或文档重新编码，实际成功读取同一 V3
revision、4,934 文件及只读 `280788 × 512 float32` memmap。完整 build 调用 68.234 秒，
含一次本地语义查询预热共 68.250 秒，其中生产 `_load_cache` 验证阶段 8.813 秒。
观测到路径解析恰好 4,934 次，每个源文件一次；文档编码尝试为 0。

收据 `tmp/final-cache-reload-performance.json` 记录本地模型加载、原 `.env` 和场景配置
SHA 不变、映射关闭、模型引用释放及进程退出。与较早的 104.625 秒相比，文件系统和
模型缓存温度、系统负载均有差异，不能据此精确归因每秒加速。

## 提交后的恢复状态清理

独立代码复审还发现，元数据成功原子提交后若删除完整 checkpoint 状态遇到临时占用，
原实现会把已发布的可用快照报告为构建失败。现仅在该提交后的清理步骤捕获 `OSError`
并记录警告，完整状态保留以便后续恢复；提交前的写入和验证错误仍抛出。恢复完整状态
时，旧向量路径若与刚发布路径相同，不再尝试删除当前发布文件。

三项回归验证提交后清理失败仍可正常加载已发布快照、残留完整状态安全复用，以及提交前
失败保留旧发布状态；没有为此重新计算真实资料向量。独立审查记录为
`tmp/final-index-review.md`。

## 实播暴露的混合检索尺度与上下文边界

run-05 保留了专业词误识别的真实问题。只读通道诊断发现，该问题在关键词通道的第一项
恰是冻结规范的实际规则段，词法覆盖为 `10 / 64 = 0.15625`；此前按
`0.7 × cosine + 0.3 × overlap` 排序，它未进入前二十。语义分与词法覆盖率的数值尺度
不能据此当成可互换的相关性证据。这是通用候选选择问题，不是指定文件需要加分。
诊断 `tmp/hybrid-channel-probe.json` 仅读取已验证元数据文本，没有重新证明生产缓存加载，
也没有模型、音频或 API 调用。

主查询现只编码当前问题。默认五个候选在语义和字面通道之间保留三、两个位置；任一通道
不足或重复时，将空位回填给其他正分候选。只有明确指代或与最近有效背景共享非问句
主题词时，才从相同五个位置内保留最多两个背景候选。不会把多轮旧问题直接混成主查询，
也不扩充外发片段数。旧混合数值仅作逐候选诊断，不决定整个结果的全局排序或可信度。

该修复没有关键词纠错表、项目名分支或文件名加分，不改变向量、模型或缓存身份。测试
覆盖强字面证据被旧数值加权挤掉、通道缩放、零匹配回填、重复/排除项、旧主题与纯分隔
背景等边界。独立 1,000 组纯内存随机数组复核确认预算及去重；这些检查不是实际来源
支持率或专业词准确率评估。原四题新一轮实播结果另见实播验证文档。

## 命中正文的章节主体

run-06 中一个正文片段只列出实现限制，遗漏其父标题和章节开头。回答因此把事件实现的
局限错误地写成解析模型的边界。现从同一不可变快照中的 Markdown 片段，懒解析最多
三级父标题与当前章节首个前置说明，总上下文最多 300 字；每行附带真实原片段定位。
不读当前磁盘文件、不修改命中正文、不改变排序、向量或缓存身份。客户端仍只发送原
问题及至多五条命中，章节说明属于各命中的有界来源上下文。

只读元数据诊断 `tmp/markdown-section-context-proof.json` 确认，原 lines 94–95 的命中
现携带 240 字上下文，明确指出 Stage3B 属于经典事件 Monte Carlo；标题及前文分别来自
该文件 lines 1–13、86–91、92–93。此收据用于证明上下文映射，不代替完整缓存重载或
新一轮真实回答核验。回归覆盖跨文件、代码围栏、长行切片、换节清除前文、同片段及
未来正文不能冒充前文，以及标题与说明共享预算。
